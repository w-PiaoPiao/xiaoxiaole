# 镜界消消乐（gem_battle）

一款竖屏的**消消乐战斗游戏**，Android 平台。战斗设计参考 Steam 游戏《Mirror》：
下方是消消乐棋盘，上方是战斗反馈舞台，消除宝石直接转化为伤害、护盾、治疗、
怒气与诅咒，敌人则按回合倒计时出手。

- 引擎：Flutter 3.47 / Dart 3.13，纯矢量绘制 + 程序化合成音效，**不含任何位图素材**
- 目标平台：Android（arm64），锁定竖屏 + 沉浸式全屏
- 产物：`build/app/outputs/flutter-apk/app-debug.apk`

## 玩法

### 主菜单与两种模式

应用启动进入**主菜单**（`main_menu.dart`）：继续上一局、战役模式、无尽模式、
玩法说明与设置。进行中的一局（关卡/波次、已拿强化、继承生命）在每次开局时
写进存档，中途杀掉应用也能从主菜单的「继续游戏」接着打。

- **战役模式**：六场战斗，从迷雾鬼火到终焉之影，难度逐关递增；胜利后继承
  生命（按 50% 保底 + 25% 回补）进入下一关。
- **无尽模式**：BOSS 按战役六战的原型轮换登场，每一波都比上一波更强——
  生命按 1.18 倍指数增长、攻击线性上升，从第 4 波起每 3 波多带一条
  **精英词条**（坚壁 / 嗜血 / 窒息 / 狂性 / 汲魂），名字也会换上「重铸·」
  「灾变·」「终焉·」的阶位前缀。每过一波同样发三选一强化，并启用一套
  **肉鸽抽取**（稀有度分层 + 每 3 波保底稀有，见下文），与敌人赛跑，
  看你能站到第几波（最佳波次会存档）。

### 宝石效果

所有宝石共用同一块八边切角底座（保证棋盘整洁），靠**图标**区分功能——
图标比抽象几何形状更直白，也不需要玩家先记图例，同时对色觉障碍友好。

| 宝石 | 图标 | 效果 |
| --- | --- | --- |
| 烈焰（红） | 交叉双剑 | 对敌人造成伤害 |
| 寒霜（蓝） | 盾牌 | 为玩家积累护盾 |
| 生机（绿） | 十字 | 恢复玩家生命 |
| 雷霆（黄） | 闪电 | 积攒怒气（满 100 释放必杀） |
| 诅咒（紫） | 骷髅 | 让敌人陷入易伤，受到的伤害提升 |

### 规则

- 三连消除；**四连**生成「破空」宝石（清除整行/整列）；**五连**生成「棱镜」
  （清空全场同色）；**拐角消除**生成「爆裂」宝石（清除 3x3）。
- 与强化宝石交换可以直接引爆它。
- 连锁会提升 `combo` 倍率（基础最高 2.5 倍，可以用强化抬高），因此一次布好局
  能打出成吨伤害。
- 敌人按倒计时出手，重击会提前一回合预警；单次伤害有上限，不会被一击秒杀。
  血条上的白线是它的**狂暴线**，越过之后敌人会变强——这是可以提前看到的信息。
- 六位 BOSS 各有一套行为机制与专属剪影：鬼火窃取怒气、守卫再生护盾、
  刺客高频出手、巫女禁疗、魔女残血狂暴、终焉吸血。战役从它们身上依次
  打过去；无尽模式里它们轮换登场、逐波增强。
- 卡住时点状态条上的**灯泡**按钮，落子顾问会推荐一步；关卡、星级、无尽
  最佳波次、进行中的一局与设置都会存档。

### 强化宝石组合技

两颗强化宝石换到一起时不再"各炸各的"，而是合成一个范围大得多的组合技——
这是消消乐最炸的一刻，也是"布好局"最直接的回报。

| 组合 | 名字 | 效果 |
| --- | --- | --- |
| 破空 + 破空 | 十字破空 | 整行 + 整列（15 格） |
| 破空 + 爆裂 | 破空爆裂 | 三整行 + 三整列（39 格） |
| 爆裂 + 爆裂 | 连环爆裂 | 5x5（25 格） |
| 棱镜 + 破空 | 同色风暴 | 全场同色，并铺开成它们所在的每一行与每一列 |
| 棱镜 + 爆裂 | 棱镜爆裂 | 全场同色 + 5x5 |
| 棱镜 + 棱镜 | 万象归一 | 清空整个棋盘 |

额外伤害也随之跳档：单颗破空 40、单颗棱镜 150，而十字 120、同色风暴 400、
万象归一 600。组合技范围内如果还压着别的强化宝石，会继续连环引爆。

### 必杀 · 斩月

怒气满 100 后点「斩月」不再直接放，而是**进入瞄准状态**：棋盘上会实时预览
整行 + 整列的清除范围，手指移到哪就预览到哪，点（或拖到位松手）在哪里就从
哪里落下。落点选得好不好，取决于棋盘上哪种颜色堆得最多——这让必杀从一个
"到点就按"的按钮变成了一次真正的决策。

### 关卡间的三选一强化

每打赢一关（波），从三张强化里挑一张，它会一直带到最后一关。这是全局唯一的成长
曲线，也是"越打越猛"的全部来源。

- 强化是**纯数据 + 一个纯函数**（`Upgrade.apply`），从出厂档案换算出新档案，
  不改任何全局状态。
- 池子里共 26 条（14 普通 + 9 稀有 + 3 传说），覆盖伤害、暴击、护盾、治疗、
  怒气、易伤、减伤、生命上限、连锁上限、强化宝石倍率、必杀、每回合回血、
  残血爆发；部分强化有前置（例如「致命一击」要先有暴击率才抽得到）。
- **暴击是打强化才解锁的**：出厂档案的暴击率为 0，所以没吃过暴击强化的对局
  仍然完全确定、可复现——这一点是所有数值测试能守住的前提。
- 输掉重试会**保留已拿到的强化**，重试的难度不会比第一次更高。

### 无尽模式的肉鸽元素

战役只有五次选择机会，保持 14 条**普通牌**的简洁线性成长；肉鸽层（稀有度
分层、质变牌、代价牌）只在无尽模式开启。它不堆数字，而是**改变规则**——
参考 Hades 的双祝福、杀戮尖塔的保底与以撒的取舍：

- **稀有 · 联动型**：把两种资源接起来——「过量暴击」让暴击伤害的一半结成
  护盾、「溢流护盾」把治疗溢出转为护盾、「荆棘壁垒」把护盾扛下的伤害反弹
  回去、「过载引擎」把攒不下的怒气烧成伤害。
- **稀有 · 棋盘质变**：消消乐专属的爽点——「棱镜宗师」让棱镜多清一种
  颜色、「爆破工程」把爆裂扩大成 5x5、「十字破空」让破空同时清整行整列。
  规则通过 `BoardRules` 显式注入棋盘引擎（含必杀与落子顾问的推演），
  不传规则的地方行为逐字不变。
- **稀有 · 代价型**：张力来自取舍——「血契」全部伤害 +50%，但每回合自损
  5 点生命（**可以致死**）；「苦修」红伤 +90%、暴击 +10%，但从此无法获得
  护盾。卡片上有红点与红字提示，代价写在明面上。
- **传说**：整局围着它转——「瘟疫」让易伤永续且每层放大强化宝石伤害、
  「永动连锁」把连锁上限抬到 5.0、「月华」让必杀消耗 -40% 且每回合自动
  蓄怒。
- **稀有度与保底**：稀有/传说的抽取权重随波次上升并封顶；第 3 波起每 3 波
  保底一张稀有以上。前置门槛只决定"能不能出现"——build 会自然长出方向感，
  与 Hades 的双祝福同一思路。
- **强度口径**（`tool/balance_report.dart`，24 种子）：输出优先中位 17 波
  （改造前 16）、保命优先 32 波；单局最差/最佳约 8 ~ 38 波，build 质量
  开始决定你能走多远。`test/endless_test.dart` 的波次窗口守着这条数据。

### 打击反馈的分级

- 连锁按深度分四档：`连击 x2`（金）→ `强袭`（橙）→ `暴走`（红）→ `无双`
  （亮金），字号、颜色与震屏力度逐档加重。
- 暴击有独立演出：伤害飘字放大到 46 号并改成金色，定格时间从 0.05 秒拉到
  0.11 秒，额外补一道金色斩击与专属音效。
- 玩家一侧的四条飘字（治疗 / 护盾 / 怒气 / 易伤）走**左右两条分道 + 上下错开**，
  一次连锁同时产出四条也不会糊成一团。

### 架构约定

- **引擎与表现分离**：`BoardEngine` 只做棋盘演算并返回一串 `CascadeStep`，
  每一步都带齐动画所需的全部信息（被清除的宝石、生成 / 引爆的强化宝石、
  结算后的棋盘快照、新宝石的入场位置）。UI 层按顺序播放即可，
  不需要反过来查询引擎状态。
- **战斗与棋盘解耦**：`BattleState` 只接收「各色宝石清除了几个」，
  不关心棋盘长什么样，因此可以脱离 UI 完整推演整场战斗。
- **成长档案不可变**：`PlayerProfile` 只有 final 字段，强化通过 `copyWith`
  换出一份新档案。战斗只读它、从不改它，所以跨关卡的成长不会反过来污染
  全局默认值——`test/simulation_test.dart` 里有一条用例专门守着这一点。
- **随机只出现在两处**：棋盘补新宝石、以及**暴击**。暴击率出厂为 0，
  没有暴击强化时 `_rollCrit` 连随机数都不消耗，所有伤害结算保持完全确定。

### 界面检查工具

`tool/ui_preview.dart` 会按真实机型尺寸渲染完整的 GameScreen，把入场卡、战斗、
玩法说明、菜单、落子提示、组合技演出、必杀瞄准、结算与三选一强化等界面各截
一张 PNG 到 `build/ui_preview/`，**并在多种屏幕尺寸与字体缩放下断言"没有任何
布局溢出"**——同一个文件同时是预览器和回归测试。它在 320x568 + 系统字体 1.5
倍的组合下抓到过真实缺陷，所以默认用例里就带着这几个小屏场景。

它还能**自己把一关打完**：棋盘与战斗状态都是 widget 的公开字段，预览可以直接
读出来交给落子顾问，于是"只有赢了才会出现"的界面（强化面板、带强化的菜单）
也进得了截图。几个只在极端情况下才暴露的问题就是这样找出来的——一次连锁同时
弹出的四条飘字糊在一起、小屏状态条挂上护盾后溢出 2.3 像素。

> 画布上的文字（连击提示、伤害飘字）走的是 `CustomPaint`，拿不到主题字体，
> 在测试环境里会全部渲染成实心方块。`paint_utils.dart` 为此留了一个
> `debugCanvasFontFamily` 钩子（生产环境为 null，行为不变），预览工具把它指向
> 注册好的中文字体，这些文字才进得了截图。

`tool/zoom.dart` 可以把预览图的任意局部放大保存，用来确认缩略之下看不清的
细节：

```bash
flutter test tool/zoom.dart --dart-define=SRC=build/ui_preview/13_max_text.png \
  --dart-define=X=170 --dart-define=Y=80 --dart-define=W=140 --dart-define=H=70
```

### 音效与触感

`lib/ui/sfx.dart` 是唯一的反馈入口，所有调用都是"尽力而为"——音频插件在
无声设备或解码失败时不影响游戏，测试环境（`FLUTTER_TEST`）直接跳过加载。

- **触感**用系统 `HapticFeedback`：选中是轻点、消除是轻击、命中随伤害加重、
  受击与必杀是重击，全部零依赖。
- **音效**由 `tool/sfx_generator.dart` 程序化合成：正弦谐波 + ADSR 包络 + 扫频，
  输出 16-bit PCM WAV 到 `assets/sfx/`（共 208 KB、11 个音效）。消除音按连击
  分三档升调，强化宝石生成/引爆分别是上扬与下坠，打击、暴击、受击、必杀、
  胜负各有专属音色。暴击音是金属撞击的"当啷"，比普通命中的闷响亮得多——
  一耳朵就能听出这一下不一样。改音色参数后重跑该脚本即可，不需要外部素材。
- 每种音效用一个 3 人播放器池轮转，连续触发不会自己打断自己；播放器以
  `PlayerMode.lowLatency` 预加载，保证跟手。

### 界面、流程与可访问性

- **主菜单**（`main_menu.dart`）是应用首页：继续游戏、战役 / 无尽模式、
  玩法说明与设置（含二次确认的「清空全部进度」）。进行中的一局每次开局
  都写进存档，主菜单的「继续游戏」能原样恢复关卡/波次、强化与继承生命。
- **暂停菜单**（`menu_overlay.dart`）同时承担本局强化清单、关卡选择（战役）、
  设置开关、回主菜单与重开，存档在 `shared_preferences`（关掉应用不会丢进度）。
- **结算面板**给出星级（按剩余生命）、最大连击与总伤害，并把最佳记录写进存档；
  无尽模式改为展示最佳波次，倒下即终局（提供「再来一局」与「回主菜单」）。
  有强化可选时战绩会压成两行，把小屏上的空间让给三张强化卡。
- **HUD 上的字号上限为 1.3 倍**（`MediaQuery.withClampedTextScaling`）：
  棋盘是固定比例的几何布局，字号无上限放大会直接把血条和按钮挤爆。
- **窄屏（< 380 像素）用紧凑文案**：血条的「300/300+40」压成「300+40」、
  怒气「18/100」压成「18」，提示按钮从 44 收窄到 38。320 像素屏 + 系统最大
  字体时，状态条是在这个组合下被挤爆过的。
- 系统开启"减少动态效果"时会自动关掉屏幕震动与闪光；设置里也能单独关。
- 血条、必杀按钮、关卡入口、开关都带了 `Semantics` 语义与 `tooltip`，
  读屏软件可以朗读关键状态。

### 数值平衡

`tool/balance_report.dart` 分两段。

**第一段：单关难度**——用出厂档案把每一关各推演 14 次，输出胜率、平均回合与
残血比例：

```
关卡 敌人        血量  正常:胜/负/僵  回合  我方残血     莽夫:胜/负  回合  莽夫残血  敌出手
1    迷雾鬼火        2600  14/0/0       9.6  300/300    14/0       8.0   300/300  2.1
6    终焉之影        7400  14/0/0       20.4 281/300    14/0       21.5  300/300  9.9
```

**第二段：整场挑战的成长曲线**——从第一关连打到最后一关，每赢一关按策略吃掉
一条强化，生命按 50% 保底续到下一关。这一段才是玩家真实经历的曲线：

```
策略    通关  第1关残血  第3关残血  终关残血  终关回合  未过卡在  典型 build
first   9/10  100%       99%        90%       16.9      5         critx2 ragex1 vitalityx1 bladex1
damage  10/10 100%       98%        90%       16.5      -         critx3 specialx1 bladex1 ultimatex1
survival8/10  100%       98%        75%       23.6      6,5       vitalityx2 healx2 ragex1 regenx1
```

（这些数字来自一次代表性运行；棋盘与抽牌都带随机，重跑的胜率与回合数会有
几个百分点的浮动。确定的只有敌人的血量与攻击。）

三种 build（随便选 / 纯输出 / 纯保命）绝大多数都能通关，说明抽牌不会把人抽进
死路；但终关普遍只剩九成血、个别 seed 卡关——这是刻意调出来的压力区间。

一段难度的校准史，值得记下：最早版本的报告里 AI 每关满血、连"莽夫打法"
都不掉血，结论是**游戏偏简单**。排查发现真正的失衡不在敌人的血量与攻击，
而在玩家的**回复经济**——蓝宝石护盾一项就吸收了敌人 85% 的输出（护盾免费
赠送、随消除自动累积）。所以这轮调整动了三个层面：

1. 敌人数值整体上调（血量 +18%~68%、攻击上调、巫女禁疗延长），攻击刻意
   定在「普攻接近单次伤害封顶（65% 最大生命）、重击顶满封顶」的位置——
   重击倍率失效的攻击是没有意义的。
2. 回复效率下调：蓝宝石护盾 20→13、绿宝石治疗 28→21。防守依然是策略，
   但不再是"免费永动机"。
3. 跨关继承削弱：60% 保底 + 35% 回补 → 50% + 25%，上一关的失误会带一点
   代价进下一关。

报告的第三段是无尽模式的推演（输出优先 build）：

```
无尽模式（肉鸽层开启：稀有度随波次上升 + 每 3 波保底稀有）
策略        最差  中位  最佳   典型 build
damage      8     17    38     critx4 bladex3 cursex2 critDamagex2
survival    11    32    38     guardx6 regenx5 bladex4 vitalityx4
```

两种策略的中位相差 15 波——build 质量（拿没拿到质变牌、有没有避开代价牌）
开始决定你能走多远，这正是肉鸽层要的形状。注意落子顾问会遍历全部 112 个相邻
交换去挑最赚的一步，而人类玩家做不到这个（人类大约是它 60% 的效率、1.6 倍的
回合数）。所以这组数字的作用是**相对测量**（改动前后对比、极端 build 会不会
卡死），不是"人类玩家会打得多轻松"——按上面的换算，战役对普通玩家是「后期
关卡需要认真防守、偶尔要重试」，无尽模式大约在第 9~16 波倒下，两条曲线都留了
继续进步的空间。

> 修过一条 bug 后这组数字变过一次：输出优先的早期成绩（最佳 52 波）里有几个
> seed 是被迫吃了「苦修」后**照旧产盾**（溢流 / 暴击转盾绕过了"无法获得护盾"），
> 修复后它们的真实成绩回落到 38 波。报告里的 damage 策略会在没有输出牌时
> 退化成拿第一张，所以它本来就模拟"运气差、被迫吃代价牌"的玩家——这条路径
> 上的数据对护盾机制的修复特别敏感。

改数值后请重跑该脚本与 `test/simulation_test.dart`——它们能挡住「关卡无解」
「打不完的僵局」「不合理的秒杀」「强化把玩家抽死」这几类问题（终焉之影的
吸血复活 bug 就是这么发现的）。

## 打击演出

攻击动画按**宝石类型**区分，玩家一眼能看出"这一下是什么打的"：

| 宝石 | 演出 |
| --- | --- |
| 红 · 交叉双剑 | 两道锥形剑气自上而下交叉斩过敌人，边缘带白芒 |
| 黄 · 闪电 | 从天而降的折线落雷，带分叉与落点闪光 |
| 紫 · 骷髅 | 骷髅印记烙在敌人身上，两道符文环向外扩散 |
| 绿 · 十字 | 治疗十字升起，绿色光点上浮（玩家一侧） |
| 蓝 · 盾牌 | 六边护盾张开，盾面有一道扫光 |
| 必杀 · 斩月 | 金色月牙形剑气横贯战场，白色锋芒 + 月华余韵 + 起手闪 |
| 暴击 | 在上面这一类的基础上再叠一层：金色斩击 + 伤害飘字放大到 46 号 + 定格翻倍 |
| 组合技 | 棋盘中央报出招式名（十字破空 / 同色风暴 / 万象归一…）+ 20 点震屏 |

打击感来自三件事：**先出手再命中**（剑气先扫过，0.09 秒后才结算伤害与数字）、
**命中定格**（命中瞬间时间放慢到 1/10，顿一下）、**敌人后仰 + 白闪 + 屏幕震动**，
强度都随伤害大小缩放。敌人攻击玩家时则有三道红色爪痕划过玩家一侧。

特效绘制集中在 `lib/ui/combat_art.dart`，可以用 `flutter test tool/fx_preview.dart`
把每种特效按真实战斗区比例渲染成图片来校对（`build/fx_preview/`），
不必反复在设备上抢帧。

> 注意：`dart:ui` 的 `Gradient` 在颜色数超过 2 时必须显式给出 `colorStops`，
> 否则绘制时会抛 `ArgumentError`。由于异常会中断整次 `paint`，排在后面的
> 内容（打击特效、伤害飘字）会全部消失——排查"某类特效不显示"时优先查这里。

## 棋盘渲染的可靠性设计

消消乐最常见、也最难查的 bug 是「宝石卡住不动 / 清完不补」，它的成因通常在
动画时序而不在游戏逻辑。这里的处理方式是一层层兜住，让棋盘在物理上不可能
出现空洞：

1. **绘制以引擎为准**（`board_view.dart`）：引擎棋盘是唯一事实来源，视觉层
   只负责提供动画位置。已经落定的宝石一律画在目标格；视觉层里缺失的宝石
   直接按格子位置补画。无论动画时序出什么意外，棋盘都不会空。
2. **空闲巡检**（`game_screen.dart` 的 `_ensureVisualSync`）：空闲时每秒比对
   一次「引擎棋盘 vs 视觉层」，检查宝石身份、目标坐标，以及已停宝石是否真的
   落在目标格上；一旦不一致就打印现场并按引擎重画。
3. **引擎空洞兜底**：`BoardEngine.countHoles/refillHoles` 会在极端情况下补满
   棋盘——正常情况下这两个函数只会返回 0。
4. **`settle()` 超时**：动画配套的等待带 3 秒超时，任何意外都不会把玩家操作
   永久锁死（配合第 1 条，提前放行也不会看到空洞）。
5. **动画等待有上限**：每段连锁最多等动画 0.42 秒（动画只是表现，引擎早已算完），
   因此再长的连锁也不会把玩家晾住。
6. **胜负定局后动画提速**：击杀 BOSS 的那一下往往带出一长串后续连锁，
   一旦判定胜负就把后续动画提速到 0.3 倍，尽快进入结算。
7. **定局兜底**：胜负已定却超过 6 秒还没弹出结算（长连锁、低帧率都可能拖住），
   直接补上结算并放开操作；只在 `battle.isOver` 时生效，不会打断正常对局。

### 性能注意

这台机器的测试环境是软件光栅化（SwiftShader），绘制开销会被放大，正好用来做
**相对测量**：`tool/perf_report.dart` 把各个 `CustomPainter` 在真实尺寸下逐帧
绘制 + 光栅化，取多轮最小值（单次测量受系统负载影响能差 20%），输出每帧毫秒数。
改动绘制代码后用它对比，别只凭感觉。

一次完整的优化过程留下了这样的数字（411x914 竖屏，软件光栅化）：

| 项目 | 优化前 | 优化后 |
| --- | --- | --- |
| 棋盘（全量重绘） | 13.3 ms | **9.8 ms**（动态层） |
| 战斗区（全量重绘） | 6.9 ms | **2.6 ms**（动态层） |
| 空闲时每帧 | 20.2 ms | **≈0 ms 棋盘 + 2.6 ms 战斗区** |

做法是四件事：

1. **静态内容分层**。棋盘的底板与 64 个凹槽、战斗区的渐变背景与光晕都是常量，
   拆成独立的 `CustomPaint`（`shouldRepaint => false`），改造前它们跟着动画
   每帧重画，一帧要画 128 个圆角矩形加三个大面积渐变。
2. **绘制改在单位空间里做**。宝石的路径、描边宽度、渐变全部按 0~1 定义，
   实际位置交给 `canvas.translate/scale`；每种颜色预建一套 `Paint` 与 `Shader`
   长期复用。改造前每颗宝石每帧都要新建 3 个渐变着色器与若干 Paint，
   64 颗就是每帧两百多个对象。
3. **棋盘没有活动时一帧都不画**。`FxController.boardRepaint` 是一个只给棋盘用的
   重绘信号：宝石全部落定、没有粒子、没有选中脉冲时不发通知。玩家思考落点的
   时间占一局里的大半，这时棋盘是彻底静止的。棋盘另外套了 `RepaintBoundary`，
   否则战斗区那侧的逐帧重绘会把它一起拖下水——这一条是关键，少了它前面的
   优化等于没做。
4. **角色的剪影按 1/8 秒量化后录成 `Picture` 复用**。它的摆动是 0.15~0.2 Hz 的
   低频运动，量化肉眼分辨不出，但省掉了每帧重建五个复杂 Path 与二十来个
   渐变着色器。受击白闪与消散粒子是逐帧变化的，这两种状态直接实时绘制。

另外还有两处小改动：飘字淡出改成把透明度编进颜色，不再为每个飘字申请
`saveLayer` 离屏缓冲；回合预警点的脉冲由它自己的 `AnimationController` 驱动，
只在敌方即将出手时运行，不再让 HUD 跟着 `fx` 每帧重建。

> 排查提示：棋盘在**消除动画进行中**本来就会短暂出现「下方几行为空」——
> 那是新宝石正在从棋盘上方落下的正常中间帧（约 0.3~0.5 秒）。判断是不是真
> 出问题，看它是否在 1 秒内自行补满；若真的卡住，日志里会有带 `⚠️` 的现场信息。

对应的回归测试在 `test/board_invariant_test.dart`：把引擎与视觉层按 UI 的真实
顺序跑几百步，每一步都断言「引擎无空洞、快照与引擎逐格一致、视觉层与引擎一致」。
`test/fx_test.dart` 则盯着"什么时候该重绘、什么时候必须安静"，以及震屏偏移的
生成与归零。

## 本机构建环境说明

这台机器处于中国大陆网络，直连 Google / Maven 官方仓库时大文件会中途停滞。
以下改动让构建跑通，**均不涉及业务代码**：

1. `~/.gradle/gradle.properties` 指向补入了本机根证书的信任库
   （`~/.gradle/truststore-mitm.jks`），解决 JVM 不信任本机代理导致的 PKIX 失败。
2. `~/.gradle/init.d/00-aliyun-mirror.gradle` 在 settings 求值前把本地仓库与
   阿里云镜像插到最前，官方仓库兜底。Flutter SDK 自带的 gradle 插件模块是一个
   独立构建，只有 init 脚本能覆盖到它。
3. `~/gradle-local-repo` 是本地 Maven 仓库，存放体积较大、官方源容易断流的构件
   （如 54MB 的 kotlin-compiler-embeddable）。
4. `android/settings.gradle.kts` 与 `android/build.gradle.kts` 同样把阿里云镜像
   排在官方源之前。
5. 构建时设置 `FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`，
   让 Flutter 引擎构件走国内镜像。

在正常网络环境下，第 1、2、3、5 条都可以省略。
