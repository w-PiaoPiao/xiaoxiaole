# 镜界消消乐（gem_battle）

一款竖屏的**消消乐战斗游戏**，Android 平台。战斗设计参考 Steam 游戏《Mirror》：
下方是消消乐棋盘，上方是战斗反馈舞台，消除宝石直接转化为伤害、护盾、治疗、
怒气与诅咒，敌人则按回合倒计时出手。

- 引擎：Flutter 3.47 / Dart 3.13，纯矢量绘制 + 程序化合成音效，**不含任何位图素材**
- 目标平台：Android（arm64），锁定竖屏 + 沉浸式全屏
- 产物：`build/app/outputs/flutter-apk/app-debug.apk`

## 玩法

### 主菜单与两种模式

应用启动进入**主菜单**（`main_menu.dart`）：继续上一局、战役模式、无尽模式、
玩法说明与设置。进行中的一局（关卡/波次、已拿强化、继承生命）在每次开局时
写进存档，中途杀掉应用也能从主菜单的「继续游戏」接着打。

- **战役模式**：十三场战斗。十三位守门的美少女——从迷雾之森的妖精茉黎到
  裂隙尽头的观测者艾诺拉——各有出身故事、开场台词与专属技能，难度逐关
  递增；胜利后继承生命（按 50% 保底 + 25% 回补）进入下一关。
- **无尽模式**：十三位美少女按序轮换登场，每一波都比上一波更强——
  生命按 1.13 倍指数增长、攻击线性上升，从第 4 波起每 3 波多带一条
  **精英词条**（坚壁 / 嗜血 / 窒息 / 狂性 / 汲魂；已自带同类机制的角色
  不再叠加），名字也会换上「重铸·」「灾变·」「终焉·」的阶位前缀。
  每过一波同样发三选一强化，并启用一套
  **肉鸽抽取**（稀有度分层 + 每 3 波保底稀有，见下文），与敌人赛跑，
  看你能站到第几波（最佳波次会存档）。
- **僵持会要命**：同一波里磨到第 100 个回合之后，敌人每 12 回合的攻击 +12%。
  这一条不针对任何 build——正常一波在 20~30 回合内结束，碰都碰不到它；
  它堵的是"输出跟不上、双方都不掉血"的无限平局。想站得久，就得打得快，
  这是无尽模式里伤害第一次有了直接的生存价值。

### 宝石效果

所有宝石共用同一块八边切角底座（保证棋盘整洁），靠**图标**区分功能——
图标比抽象几何形状更直白，也不需要玩家先记图例，同时对色觉障碍友好。

| 宝石 | 图标 | 效果 |
| --- | --- | --- |
| 烈焰（红） | 交叉双剑 | 对敌人造成伤害 |
| 寒霜（蓝） | 盾牌 | 为玩家积累护盾 |
| 生机（绿） | 十字 | 恢复玩家生命 |
| 雷霆（黄） | 闪电 | 积攒怒气（满 100 释放必杀） |
| 诅咒（紫） | 骷髅 | 让敌人陷入易伤，受到的伤害提升 |

### 规则

- 三连消除；**四连**生成「破空」宝石（清除整行/整列）；**五连**生成「棱镜」
  （清空全场同色）；**拐角消除**生成「爆裂」宝石（清除 3x3）。
- 强化宝石和普通宝石遵守同一条规则：**换出一个消除才会引爆**（被消除波及时
  同样引爆）。两个例外——棱镜没有颜色、参与不了匹配，与任意相邻宝石交换都
  是它的用法；两颗强化宝石换到一起是组合技，与匹配无关。
- 连锁会提升 `combo` 倍率（基础最高 2.5 倍，可以用强化抬高），因此一次布好局
  能打出成吨伤害。
- 敌人按倒计时出手，重击会提前一回合预警；单次伤害有上限，不会被一击秒杀。
  血条上的白线是它的**狂暴线**，越过之后敌人会变强——这是可以提前看到的信息。
- **多管血 BOSS**：战役后两关与无尽模式的高波次敌人有多管血——血条后面
  挂着 **×N** 徽标，N 是剩余管数（含正在打的那一管）。每管刻意压小，
  一次布好的连锁就能打掉血条的一大截；打空一管时徽标立刻减 1、血条同时
  回满，看到的永远是"又一管被打掉了"，不会出现一条空血条。打空一管不等于
  赢：敌人满血进入下一形态，身上的易伤与护盾清零、出手倒计时重置，攻击还
  逐管变强——每打空一管都要把优势重新建立一遍。溢出的伤害不会带到下一管，
  每一管都得实打实地打空。
- **十三位美少女，一人一机制一立绘**：除了出手节奏、护盾再生、吸血、禁疗、
  狂暴这些基础机制，每位还有一个每几次出手亮一次的**专属技能**——妖精自愈、
  圣女结壁、忍者分身、魔女下毒、魅魔夺盾、月祭司偷怒、人鱼回血、冰姬冰甲、
  吸血鬼血宴、傀儡师缠盾、机关巫姬过载、龙女贯穿、观测者星噬。技能回合会
  提前一回合报出技能名与预计伤害；中毒、结界会以状态标签常驻血条旁。
  立绘是纯矢量自绘（`ui/enemy_art.dart`：一份共享的美少女身形 + 每人一套
  发型配色与特色图层），`flutter test tool/boss_preview.dart` 可以把十三人
  渲染到一张 PNG 里核对造型。战役从她们身上依次打过去；无尽模式里她们
  轮换登场、逐波增强。
- 卡住时点状态条上的**灯泡**按钮，落子顾问会推荐一步；关卡、星级、无尽
  最佳波次、进行中的一局与设置都会存档。

### 强化宝石组合技

两颗强化宝石换到一起时不再"各炸各的"，而是合成一个范围大得多的组合技——
这是消消乐最炸的一刻，也是"布好局"最直接的回报。

| 组合 | 名字 | 效果 |
| --- | --- | --- |
| 破空 + 破空 | 十字破空 | 整行 + 整列（15 格） |
| 破空 + 爆裂 | 破空爆裂 | 三整行 + 三整列（39 格） |
| 爆裂 + 爆裂 | 连环爆裂 | 5x5（25 格） |
| 棱镜 + 破空 | 同色风暴 | 全场同色，并铺开成它们所在的每一行与每一列 |
| 棱镜 + 爆裂 | 棱镜爆裂 | 全场同色 + 5x5 |
| 棱镜 + 棱镜 | 万象归一 | 清空整个棋盘 |

额外伤害也随之跳档：单颗破空 40、单颗棱镜 150，而十字 120、同色风暴 400、
万象归一 600。组合技范围内如果还压着别的强化宝石，会继续连环引爆。

### 必杀 · 斩月

怒气满 100 后点「斩月」不再直接放，而是**进入瞄准状态**：棋盘上会实时预览
整行 + 整列的清除范围，手指移到哪就预览到哪，点（或拖到位松手）在哪里就从
哪里落下。落点选得好不好，取决于棋盘上哪种颜色堆得最多——这让必杀从一个
"到点就按"的按钮变成了一次真正的决策。

怒气按每颗黄宝石 4 点积累，推演口径下一局约 2 次：必杀是**攒出来的大招**，
不是常规输出手段。9 点/颗的旧口径下一局能放近 5 次，几乎每个回合都要"选
斩月再选落点"，把消消乐的节奏切得七零八落。

### 局内道具

每关（波）开局，道具栏会补足到**三样各一件**——用掉不累积、也不会清零，
它是一个"每关一次的急救包"：

| 道具 | 效果 |
| --- | --- |
| 锤子 | 点掉任意一格（强化宝石直接引爆；机关连壳砸碎）。点按钮后进入瞄准态，棋盘上出现取景框，点/拖到哪就砸哪 |
| 洗牌 | 重新排列棋盘颜色（机关原样保留） |
| 凝滞 | 敌方出手推迟 1 回合——倒计时满格时用不出来，也不会消耗 |

**道具不消耗回合**：用完不推进敌人的出手倒计时，这是它们"救场"的意义所在；
数量有限来平衡。危机关头（敌人下一击挡不住、手里还有道具）道具栏会亮起
危险色——提示只在真正需要的那一刻出现，而不是一直挂着。

### 棋盘机关

机关是**附着在宝石上的障碍物**——被机关锁住的宝石不能交换、不参与匹配。
破除口径分两档：被消除 / 爆炸**直接命中**的机关格连壳带石一起清掉（宝石随
清除结算消失，与锤子同一条"砸碎"口径）；仅被**波及**（在清除格的四邻上）
的机关格只破壳，宝石显形留在棋盘上。它们**跟着宝石一起下落**，所以棋盘
永远不会有空洞。

| 机关 | 效果 | 与战斗的绑定 |
| --- | --- | --- |
| 冰封 | 锁住宝石，命中/波及均可破除 | 纯棋盘压力：占用格子、打断布局 |
| 毒藤 | 锁住宝石，命中/波及均可破除 | **每株让敌人攻击 +5%**，清掉才停 |
| 祭坛 | 锁住宝石，命中/波及均可破除 | **破除时立刻 +20 怒气**，清障即收益 |

机关是**关卡的配置**而不是敌人的技能：战役第 3~13 关各配一组、逐关换花样；
无尽模式从第 4 波起（与精英词条同步）每 3 波多一件，毒藤封顶 3 株。同一个
关卡每次开局摆放位置随机，但用棋盘专属的随机源——**不扰动宝石序列**，
平衡报告里改机关数量的前后对比才有可比性。

### 关卡间的三选一强化

每打赢一关（波），从三张强化里挑一张，它会一直带到最后一关。这是全局唯一的成长
曲线，也是"越打越猛"的全部来源。

- 强化是**纯数据 + 一个纯函数**（`Upgrade.apply`），从出厂档案换算出新档案，
  不改任何全局状态。
- 池子里共 30 条（14 普通 + 12 稀有 + 4 传说），覆盖伤害、暴击、护盾、治疗、
  怒气、易伤、减伤、生命上限、连锁上限、强化宝石倍率、必杀、每回合回血、
  残血爆发与斩杀；部分强化有前置（例如「致命一击」要先有暴击率才抽得到）。
  肉鸽层里有专门的**生存型**稀有牌（山岳之躯、圣盾壁垒）与保命传说「不屈」
  （把单次受击上限从 65% 压到 40%，僵持惩罚可以穿透它）——多管血 BOSS 逐击
  变凶之后，"活下去"是一条独立的成长路线，不必和输出抢位置。
  每张牌的 `available` 前置链都有**可达性元测试**守着：全叠满配置下任何一张
  牌都必须可抽，防止「过载引擎」那样的死牌事故（yellowRage 从 9 削到 4 时
  门槛没跟着改，一张稀有牌静默失效了半年）。
- **暴击是打强化才解锁的**：出厂档案的暴击率为 0，所以没吃过暴击强化的对局
  仍然完全确定、可复现——这一点是所有数值测试能守住的前提。
- 输掉重试会**保留已拿到的强化**，重试的难度不会比第一次更高。

### 无尽模式的肉鸽元素

战役只有十二次选择机会，保持 14 条**普通牌**的简洁线性成长；肉鸽层（稀有度
分层、质变牌、代价牌）只在无尽模式开启。它不堆数字，而是**改变规则**——
参考 Hades 的双祝福、杀戮尖塔的保底与以撒的取舍：

- **稀有 · 联动型**：把两种资源接起来——「过量暴击」让暴击伤害的一半结成
  护盾、「溢流护盾」把治疗溢出转为护盾、「荆棘壁垒」把护盾扛下的伤害反弹
  回去、「过载引擎」把攒不下的怒气烧成伤害、「处决者」在敌人残血时把红宝石
  伤害再抬一截（乘在伤害乘区里，收尾阶段越打越狠）。
- **稀有 · 棋盘质变**：消消乐专属的爽点——「棱镜宗师」让棱镜多清一种
  颜色、「爆破工程」把爆裂扩大成 5x5、「十字破空」让破空同时清整行整列。
  规则通过 `BoardRules` 显式注入棋盘引擎（含必杀与落子顾问的推演），
  不传规则的地方行为逐字不变。
- **稀有 · 代价型**：张力来自取舍——「血契」全部伤害 +50%，但每回合自损
  5 点生命（**可以致死**）；「苦修」红伤 +90%、暴击 +10%，但从此无法获得
  护盾。卡片上有红点与红字提示，代价写在明面上。
- **传说**：整局围着它转——「瘟疫」让易伤永续且每层放大强化宝石伤害、
  「永动连锁」把连锁上限抬到 5.0、「月华」让必杀消耗 -40% 且每回合自动
  蓄怒。
- **稀有度与保底**：稀有/传说的抽取权重随波次上升并封顶；第 3 波起每 3 波
  保底一张稀有以上。前置门槛只决定"能不能出现"——build 会自然长出方向感，
  与 Hades 的双祝福同一思路。
- **强度口径**（`tool/balance_report.dart`，24 种子、含机关）：输出优先中位
  14 波、保命优先 25 波；单局最差/最佳约 10 ~ 60 波，build 质量开始决定
  你能走多远。`test/endless_test.dart` 的波次窗口守着这条数据，推演器与报告
  共用 `test/support/sim.dart` 的同一份口径（摆机关、同步毒藤、注入棋盘规则）；
  同文件还守着「每一局的失利都必须是**被打死**，而不是磨到回合耗尽」——
  见下文「僵持会要命」。

### 打击反馈的分级

- 连锁按深度分四档：`连击 x2`（金）→ `强袭`（橙）→ `暴走`（红）→ `无双`
  （亮金），字号、颜色与震屏力度逐档加重。
- 暴击有独立演出：伤害飘字放大到 46 号并改成金色，定格时间从 0.05 秒拉到
  0.11 秒，额外补一道金色斩击与专属音效。
- 玩家一侧的四条飘字（治疗 / 护盾 / 怒气 / 易伤）走**左右两条分道 + 上下错开**，
  一次连锁同时产出四条也不会糊成一团。

```

  engine/             纯 Dart 逻辑层，可脱离 Flutter 单测
    gem.dart          宝石 / 强化宝石 / 机关 / 快照等基础数据结构
    board.dart        棋盘引擎：匹配、连锁、重力、强化宝石引爆、机关破除、洗牌

    levels.dart       战役十三战的美少女角色配置（出身故事 / 专属技能）与
                      `PlayerProfile`（不可变的玩家属性）
    endless.dart      无尽模式：按波次生成逐波增强的 BOSS（确定性、可推演）

  ui/

    game_screen.dart  总控：输入、动画时序编排、关卡流程、结算与三选一强化
    battle_view.dart  上方战斗反馈区（角色舞台 / 血条 / 回合预警 / 飘字 / 斩击）
    board_view.dart   下方消消乐区（手势 + 棋盘绘制 + 提示高亮 + 必杀/道具瞄准预览）
    enemy_art.dart    敌方角色的矢量美术（美少女身形框架 + 十三人各自的

    gem_art.dart      五种宝石的矢量美术

    item_art.dart     道具图标（锤子 / 循环箭头 / 沙漏）
    upgrade_art.dart  强化卡片的图标（复用宝石图标 + 新符号：水滴 / 荆棘 /
                      齿轮 / 三叉 / 准星 / 血滴）
    fx.dart           特效控制器：宝石位移、粒子、飘字、震屏、机关碎裂
    hud.dart          血条 / 怒气条 / 标签 / 必杀按钮 / 回合点

                      **各占一个槽**，切模式开新局不会冲掉另一边的进度，
                      「继续游戏」恢复两个槽里较新的那一局
  main.dart           入口：锁定竖屏 + 沉浸式全屏 + 设置加载，home 是主菜单
test/                 253 个用例（含 test/support/sim.dart：与平衡报告共用推演口径）
tool/                 开发辅助脚本（见下）
```

### 架构约定

- **引擎与表现分离**：`BoardEngine` 只做棋盘演算并返回一串 `CascadeStep`，
  每一步都带齐动画所需的全部信息（被清除的宝石、生成 / 引爆的强化宝石、
  结算后的棋盘快照、新宝石的入场位置）。UI 层按顺序播放即可，
  不需要反过来查询引擎状态。
- **战斗与棋盘解耦**：`BattleState` 只接收「各色宝石清除了几个」，
  不关心棋盘长什么样，因此可以脱离 UI 完整推演整场战斗。
- **成长档案不可变**：`PlayerProfile` 只有 final 字段，强化通过 `copyWith`
  换出一份新档案。战斗只读它、从不改它，所以跨关卡的成长不会反过来污染
  全局默认值——`test/simulation_test.dart` 里有一条用例专门守着这一点。
- **随机只出现在两处**：棋盘补新宝石、以及**暴击**。暴击率出厂为 0，
  没有暴击强化时 `_rollCrit` 连随机数都不消耗，所有伤害结算保持完全确定。

### 音效与触感

`lib/ui/sfx.dart` 是唯一的反馈入口，所有调用都是"尽力而为"——音频插件在
无声设备或解码失败时不影响游戏，测试环境（`FLUTTER_TEST`）直接跳过加载。

- **触感**用系统 `HapticFeedback`：选中是轻点、消除是轻击、命中随伤害加重、
  受击与必杀是重击，全部零依赖。
- **音效**由 `tool/sfx_generator.dart` 程序化合成：正弦谐波 + ADSR 包络 + 扫频，
  输出 16-bit PCM WAV 到 `assets/sfx/`（共 208 KB、11 个音效）。消除音按连击
  分三档升调，强化宝石生成/引爆分别是上扬与下坠，打击、暴击、受击、必杀、
  胜负各有专属音色。暴击音是金属撞击的"当啷"，比普通命中的闷响亮得多——
  一耳朵就能听出这一下不一样。改音色参数后重跑该脚本即可，不需要外部素材。
- 每种音效用一个 3 人播放器池轮转，连续触发不会自己打断自己；播放器以
  `PlayerMode.lowLatency` 预加载，保证跟手。

### 界面、流程与可访问性

- **主菜单**（`main_menu.dart`）是应用首页：继续游戏、战役 / 无尽模式、
  玩法说明与设置（含二次确认的「清空全部进度」）。进行中的一局每次开局
  都写进存档，主菜单的「继续游戏」能原样恢复关卡/波次、强化与继承生命。
- **暂停菜单**（`menu_overlay.dart`）同时承担本局强化清单、关卡选择（战役）、
  设置开关、回主菜单与重开，存档在 `shared_preferences`（关掉应用不会丢进度）。
  注意它**不是硬暂停**：打开菜单只屏蔽输入，在飞的连锁演出与敌方回合仍会在
  遮罩后面走完——菜单标题下常驻一行当前生命/护盾，玩家随时能盯着自己的血线。
- **结算面板**给出星级（按剩余生命）、最大连击与总伤害，并把最佳记录写进存档；
  无尽模式改为展示最佳波次，倒下即终局（提供「再来一局」与「回主菜单」）。
  有强化可选时战绩会压成两行，把小屏上的空间让给三张强化卡。
- **HUD 上的字号上限为 1.3 倍**（`MediaQuery.withClampedTextScaling`）：
  棋盘是固定比例的几何布局，字号无上限放大会直接把血条和按钮挤爆。
- **窄屏（< 380 像素）用紧凑文案**：血条的「300/300+40」压成「300+40」、
  怒气「18/100」压成「18」，提示按钮从 44 收窄到 38。320 像素屏 + 系统最大
  字体时，状态条是在这个组合下被挤爆过的。
- 系统开启"减少动态效果"时会自动关掉屏幕震动与闪光；设置里也能单独关。
- 血条、必杀按钮、关卡入口、开关都带了 `Semantics` 语义与 `tooltip`，
  读屏软件可以朗读关键状态。

贪婪 / 保命两种 build 能通关大半种子，输出流在十三关长程下约三成通关、

这条路线的既定价签：想稳，就得拿保命牌——生存型稀有牌（山岳之躯、圣盾壁垒）
与传说「不屈」就是给这条路准备的。注意推演的"随便吃强化"（first）只是
下限读数：它会拿陷阱牌、永远用道具、必杀落点固定在棋盘中心，而真玩家
选牌、用道具、手动挑落点——三件事都比推演做得好。

一段难度的校准史，值得记下。最早版本的报告里 AI 每关满血、连"莽夫打法"
都不掉血，结论是**游戏偏简单**。排查发现真正的失衡不在敌人的血量与攻击，
而在玩家的**回复经济**——蓝宝石护盾一项就吸收了敌人 85% 的输出（护盾免费
赠送、随消除自动累积）。所以那一轮调整动了三个层面：

1. 敌人数值整体上调（血量 +18%~68%、攻击上调、巫女禁疗延长），攻击刻意
   定在「普攻接近单次伤害封顶（65% 最大生命）、重击顶满封顶」的位置——
   重击倍率失效的攻击是没有意义的。
2. 回复效率下调：蓝宝石护盾 20→13、绿宝石治疗 28→21。防守依然是策略，
   但不再是"免费永动机"。
3. 跨关继承削弱：60% 保底 + 35% 回补 → 50% + 25%，上一关的失误会带一点
   代价进下一关。

第二轮（也就是加进「最低血」这一列的那次）发现的是**同一类问题的残留**：
前四关的敌人每回合输出只有 19~61，而玩家的每回合续航是 42~71——**净收支
全为正**，玩家在打木桩，终局残血 96%~100% 只是因为这个数字看不见过程。
修法是把前两关的攻击提到「普攻逼近封顶、重击顶满封顶」的位置（62→76、
118→128），并把第三关微调 2%（106→104）让"每回合 DPS"逐关严格递增——
后三关原本就到位，不动。于是最低血变成 93/76/60/60/39/29% 的单调曲线，
莽夫流也从第 3 关起开始真正掉血。这条教训写进了报告：
**只要「最低血」的均值还在 90% 以上，就说明这一关的敌人 DPS 低于玩家的
续航，玩家是在打木桩。**

第三轮校准（2026-10-04 全局审查）修的是**推演器本身**。审查发现
`test/support/sim.dart` 与 GameScreen 有三处口径偏差，全部朝着"推演玩家比
真实玩家强"的方向：必杀不占回合（每回合既交换又放斩月，DPS 系统性偏高）、
漏了祭坛 +20 怒气、过关血量按新档案整体重算（拿生命上限牌的保命流被低估）。
口径修正后所有读数重新校准：无尽两条流的中位（15 / 25）都还在守卫窗口
[10, 36] 内；整场挑战「随便吃强化」的下限从旧口径的 12/16 落到 7/16（守卫
阈值放到 6）——旧读数是必杀红利，新读数才是推演玩家面对的世界。同一轮把
终战攻击 224 → 204（对出厂档案无感——它已经被 65% 封顶盖住；对拿到生命
强化的玩家是真实的减压），`diag_balance.dart` 的手写推演循环也收编进
`sim.fight`（工具与测试从两份口径变成一份）。教训写进了报告口径：**推演器
与真实回合管线的每一处偏差，都会以"平衡数据"的名义误导下一次调参**——
偏差方向还不一致（必杀红利推高 DPS、漏祭坛压低怒气），叠加后连偏差方向都
读不出来，必须逐条对齐。

报告的第三段是无尽模式的推演：

```
无尽模式（肉鸽层开启：稀有度随波次上升 + 每 3 波保底稀有；第 4 波起带机关）
策略        最差  中位  最佳   典型 build
damage      11    15    47     bladex2 combox2 cursex2 critx1
survival    11    25    40     mountainHeartx2 aegisWallx2 thornGuardx2 overflowGuardx2
```

生存流的中位（25）比输出流（15）高、输出流的最佳局（47 波）远深于生存流
（40 波）——这正是两条成长路线的分工："活下去"让你站得久，走得远仍然要靠
伤害。十三位角色的机制总量比旧六人大（毒、结界、贯穿、过载……），输出流
呈两极分布：爆发够的局能跑到 40~47 波，不够的会在 10~12 波的三管血撞墙。

这里曾被一条数学漏洞搅乱过，值得记下来。玩家每回合的续航会随强化线性增长，
而敌人的单次伤害被封顶保护在「最大生命的 65%」——两者相抵之后，强续航 build
会变成**不死之身**：推演里 8 局有 4 局磨满 400 回合还没分出胜负，玩家满血满盾
站着，敌人也一行血不掉。那不是"输"，是**卡住**，而无尽模式的承诺是"与敌人
赛跑，站到站不住为止"。

修法是 `EndlessRoster.attritionRamp`：同一波里磨到第 100 个玩家回合之后，敌人
每 12 回合的攻击 +12%，并且**在封顶之后结算**——封顶是"不会被一击秒杀"的
承诺，不能动，所以惩罚必须乘在它外面，否则再高的系数也会被天花板吃掉（第一版
就是这么写的，漏洞原封不动）。这条曲线的形状是刻意的：正常一波 20~30 回合，
碰都碰不到它；只有僵住的局才会被逐步收掉。附带的好处是**伤害第一次有了直接的
生存价值**——打得快就不必面对它，输出流从此有了一条独立的活路。

阈值的位置是量出来的，不是拍出来的：定在 40 回合时，保命流的中位从 23 波塌到
16 波——强续航 build 的每一波本来就要打 100 回合以上，惩罚于是从"僵持的解药"
变成了"对所有慢节奏 build 的常规惩罚"。推后到 100 之后，两条路线（17 / 23 波）
与最佳局（47 波）才同时站得住。

同一轮里还有两处配套修正：生命增速 1.18 → 1.15（血量是复利，0.03 的差别到
第 20 波就是 24% 的总血量，曲线太陡会让多管血与精英词条的"台阶感"还没被
玩家看见就先把人压死），以及 `test/endless_test.dart` 里新增的一条守卫
「输总是"被打死"，不会磨到回合耗尽」——它守的就是上面那条漏洞不会回来。

落子顾问会遍历全部 112 个相邻
交换去挑最赚的一步，而人类玩家做不到这个（人类大约是它 60% 的效率、1.6 倍的
回合数）。所以这组数字的作用是**相对测量**（改动前后对比、极端 build 会不会
卡死），不是"人类玩家会打得多轻松"——按上面的换算，战役对普通玩家是「后期
关卡需要认真防守、可能要重试几次」，无尽模式大约在第 8~14 波倒下，两条曲线
都留了继续进步的空间。

> 三点口径值得记下。其一，**AI 不使用道具**：报告量的是"只有机关、没有道具"
> 的下限，而玩家每关有三件道具（锤子的一次免费消除、凝滞的一次免伤都要算进
> 手感里）。其二，机关用**独立随机源**布点，不扰动宝石序列——所以"这一关摆
> 几件机关"的前后对比仍然可比（早期版本里机关与补位共用一个随机源，改数量会
> 连带换掉整条宝石序列，数据没法对比）。其三，修过「苦修」的护盾 bug 后，输出
> 优先的早期成绩（最佳 52 波）暴露为 bug 红利、回落到 38 波；报告里的 damage
> 策略在没有输出牌时会退化成拿第一张（可能吃到苦修），它本来就模拟"运气差、
> 被迫吃代价牌"的玩家，这条路径对护盾类改动特别敏感。

改数值后请重跑该脚本与 `test/simulation_test.dart`——它们能挡住「关卡无解」
「打不完的僵局」「不合理的秒杀」「强化把玩家抽死」这几类问题（终焉之影的
吸血复活 bug 就是这么发现的）。

报告看的是**结果**（胜率、残血、波次），要追**原因**时用 `tool/diag_balance.dart`
——它把一局的收支摊成台账：玩家每回合拿到多少护盾/治疗、敌人每回合打掉多少、
两者相减的「净」是多少。改关卡数值的顺序是：先看「净」是不是正的（正 = 玩家
在打木桩，这一关没有威胁），再看「续航/回合」决定敌人 DPS 要提到多少。
「最低血」只看报告那一列也能读出同样的结论。

## 打击演出

攻击动画按**宝石类型**区分，玩家一眼能看出"这一下是什么打的"：

| 宝石 | 演出 |
| --- | --- |
| 红 · 交叉双剑 | 两道锥形剑气自上而下交叉斩过敌人，边缘带白芒 |
| 黄 · 闪电 | 从天而降的折线落雷，带分叉与落点闪光 |
| 紫 · 骷髅 | 骷髅印记烙在敌人身上，两道符文环向外扩散 |
| 绿 · 十字 | 治疗十字升起，绿色光点上浮（玩家一侧） |
| 蓝 · 盾牌 | 六边护盾张开，盾面有一道扫光 |
| 必杀 · 斩月 | 金色月牙形剑气横贯战场，白色锋芒 + 月华余韵 + 起手闪 |
| 暴击 | 在上面这一类的基础上再叠一层：金色斩击 + 伤害飘字放大到 46 号 + 定格翻倍 |
| 组合技 | 棋盘中央报出招式名（十字破空 / 同色风暴 / 万象归一…）+ 一次重震 |

打击感来自三件事：**先出手再命中**（剑气先扫过，0.09 秒后才结算伤害与数字）、
**命中定格**（命中瞬间时间放慢到 1/10，顿一下）、**敌人后仰 + 白闪 + 屏幕震动**，
强度都随伤害大小缩放。敌人攻击玩家时则有三道红色爪痕划过玩家一侧。

震屏在触发点传的是**相对强度**（必杀 26 最重、非法交换 5 最轻），落到画面上
要经 `FxController` 统一收敛：幅度 ×0.38 并封顶 11 像素，按 62 像素/秒衰减，
最重的一击约 0.16 秒收干净。相位与衰减都走真实时间——不跟命中定格一起被
压到 1/10，否则短促的"抖"会被拖成 1 Hz 出头的"晃"，比震动本身更晕。
抖动频率约 13 / 18 Hz：原来 16 / 22 Hz 配大幅度时整个界面会糊成一片。

特效绘制集中在 `lib/ui/combat_art.dart`，可以用 `flutter test tool/fx_preview.dart`
把每种特效按真实战斗区比例渲染成图片来校对（`build/fx_preview/`），
不必反复在设备上抢帧。

> 注意：`dart:ui` 的 `Gradient` 在颜色数超过 2 时必须显式给出 `colorStops`，
> 否则绘制时会抛 `ArgumentError`。由于异常会中断整次 `paint`，排在后面的
> 内容（打击特效、伤害飘字）会全部消失——排查"某类特效不显示"时优先查这里。

## 棋盘渲染的可靠性设计

消消乐最常见、也最难查的 bug 是「宝石卡住不动 / 清完不补」，它的成因通常在
动画时序而不在游戏逻辑。这里的处理方式是一层层兜住，让棋盘在物理上不可能
出现空洞：

1. **绘制以引擎为准**（`board_view.dart`）：引擎棋盘是唯一事实来源，视觉层
   只负责提供动画位置。已经落定的宝石一律画在目标格；视觉层里缺失的宝石
   直接按格子位置补画。无论动画时序出什么意外，棋盘都不会空。
2. **空闲巡检**（`game_screen.dart` 的 `_ensureVisualSync`）：空闲时每秒比对
   一次「引擎棋盘 vs 视觉层」，检查宝石身份、目标坐标，以及已停宝石是否真的
   落在目标格上；一旦不一致就打印现场并按引擎重画。
3. **引擎空洞兜底**：`BoardEngine.countHoles/refillHoles` 会在极端情况下补满
   棋盘——正常情况下这两个函数只会返回 0。
4. **`settle()` 超时**：动画配套的等待带 3 秒超时，任何意外都不会把玩家操作
   永久锁死（配合第 1 条，提前放行也不会看到空洞）。
5. **动画等待有上限**：每段连锁最多等动画 0.42 秒（动画只是表现，引擎早已算完），
   因此再长的连锁也不会把玩家晾住。
6. **胜负定局后动画提速**：击杀 BOSS 的那一下往往带出一长串后续连锁，
   一旦判定胜负就把后续动画提速到 0.3 倍，尽快进入结算。
7. **定局兜底**：胜负已定却超过 6 秒还没弹出结算（长连锁、低帧率都可能拖住），
   直接补上结算并放开操作；只在 `battle.isOver` 时生效，不会打断正常对局。

### 性能注意

这台机器的测试环境是软件光栅化（SwiftShader），绘制开销会被放大，正好用来做
**相对测量**：`tool/perf_report.dart` 把各个 `CustomPainter` 在真实尺寸下逐帧
绘制 + 光栅化，取多轮最小值（单次测量受系统负载影响能差 20%），输出每帧毫秒数。
改动绘制代码后用它对比，别只凭感觉。

一次完整的优化过程留下了这样的数字（411x914 竖屏，软件光栅化）：

| 项目 | 优化前 | 优化后 |
| --- | --- | --- |
| 棋盘（全量重绘） | 13.3 ms | **9.8 ms**（动态层） |
| 战斗区（全量重绘） | 6.9 ms | **2.6 ms**（动态层） |
| 空闲时每帧 | 20.2 ms | **≈0 ms 棋盘 + 2.6 ms 战斗区** |

做法是四件事：

1. **静态内容分层**。棋盘的底板与 64 个凹槽、战斗区的渐变背景与光晕都是常量，
   拆成独立的 `CustomPaint`（`shouldRepaint => false`），改造前它们跟着动画
   每帧重画，一帧要画 128 个圆角矩形加三个大面积渐变。
2. **绘制改在单位空间里做**。宝石的路径、描边宽度、渐变全部按 0~1 定义，
   实际位置交给 `canvas.translate/scale`；每种颜色预建一套 `Paint` 与 `Shader`
   长期复用。改造前每颗宝石每帧都要新建 3 个渐变着色器与若干 Paint，
   64 颗就是每帧两百多个对象。
3. **棋盘没有活动时一帧都不画**。`FxController.boardRepaint` 是一个只给棋盘用的
   重绘信号：宝石全部落定、没有粒子、没有选中脉冲时不发通知。玩家思考落点的
   时间占一局里的大半，这时棋盘是彻底静止的。棋盘另外套了 `RepaintBoundary`，
   否则战斗区那侧的逐帧重绘会把它一起拖下水——这一条是关键，少了它前面的
   优化等于没做。
4. **角色的剪影按 1/8 秒量化后录成 `Picture` 复用**。它的摆动是 0.15~0.2 Hz 的
   低频运动，量化肉眼分辨不出，但省掉了每帧重建五个复杂 Path 与二十来个
   渐变着色器。受击白闪也进缓存键（量化成十档），只有消散仍走实时路径。

另外还有几处小改动：飘字淡出改成把透明度编进颜色，不再为每个飘字申请
`saveLayer` 离屏缓冲；回合预警点的脉冲由它自己的 `AnimationController` 驱动，
只在敌方即将出手时运行，不再让 HUD 跟着 `fx` 每帧重建。

再往后的第二轮优化（数字同样来自 `tool/perf_report.dart`，411x914 竖屏；
同一台机器上多次运行会差 10% 左右）：

| 项目 | 数值 |
| --- | --- |
| 棋盘（全量重绘） | **7.3 ~ 8.0 ms** |
| 战斗区（全量重绘） | **1.2 ms** |
| 飘字 x2 | **0.13 ms** |

1. **消散宝石不再逐颗开离屏层**。宝石淡出过去靠 `saveLayer`，而棱镜 / 同色
   风暴一次清三四十颗就是三四十块离屏缓冲——这是棋盘上最贵的一项。现在把
   透明度用 `BlendMode.modulate` 滤镜一次乘进所有笔触（`GemArt._applyFade`），
   重叠处的细微差别在 0.26 秒的消散里看不出来。`test/art_render_test.dart`
   用像素亮度守着"每一层都真的淡出了"。
2. **画布文字按"文本 + 样式 + 透明度档"缓存布局**。飘字在 1 秒的生命里会被
   重画五六十帧，每帧跑一次 shaping 是纯浪费；量化到 1/16 档之后，同一段
   文字只需布局十几次。
3. **机关与宝石一样用静态画笔**。一屏二十几格机关，每格每帧新建四五支
   `Paint` 是纯粹的分配浪费，只有冰裂纹与祭坛光点需要按帧改 alpha。
4. **「减少动态效果」下把持续动画收干净**：棱镜的彩色环停转（棋盘随之回到
   "静止不重绘"）、背景浮尘不再飘，战斗区也只在真的有动画时才重画。这几样
   是屏幕上唯一"永远在动"的东西，对前庭敏感的用户正是该收敛的部分。

> 排查提示：棋盘在**消除动画进行中**本来就会短暂出现「下方几行为空」——
> 那是新宝石正在从棋盘上方落下的正常中间帧（约 0.3~0.5 秒）。判断是不是真
> 出问题，看它是否在 1 秒内自行补满；若真的卡住，debug 构建的日志里会有
> 带 `⚠️` 的现场信息（release 构建不打印这些排查日志）。

对应的回归测试在 `test/board_invariant_test.dart`：把引擎与视觉层按 UI 的真实
顺序跑几百步，每一步都断言「引擎无空洞、快照与引擎逐格一致、视觉层与引擎一致」。
`test/fx_test.dart` 则盯着"什么时候该重绘、什么时候必须安静"，以及震屏偏移的
生成与归零、强度收敛与封顶、定格期间不被拖慢。

## 本机构建环境说明

这台机器处于中国大陆网络，直连 Google / Maven 官方仓库时大文件会中途停滞。
以下改动让构建跑通，**均不涉及业务代码**：

1. `~/.gradle/gradle.properties` 指向补入了本机根证书的信任库
   （`~/.gradle/truststore-mitm.jks`），解决 JVM 不信任本机代理导致的 PKIX 失败。
2. `~/.gradle/init.d/00-aliyun-mirror.gradle` 在 settings 求值前把本地仓库与
   阿里云镜像插到最前，官方仓库兜底。Flutter SDK 自带的 gradle 插件模块是一个
   独立构建，只有 init 脚本能覆盖到它。
3. `~/gradle-local-repo` 是本地 Maven 仓库，存放体积较大、官方源容易断流的构件
   （如 54MB 的 kotlin-compiler-embeddable）。
4. `android/settings.gradle.kts` 与 `android/build.gradle.kts` 同样把阿里云镜像
   排在官方源之前。
5. 构建时设置 `FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`，
   让 Flutter 引擎构件走国内镜像。

在正常网络环境下，第 1、2、3、5 条都可以省略。
